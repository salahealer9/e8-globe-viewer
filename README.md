# E8 Alignment Viewer

[![DOI](https://zenodo.org/badge/DOI/10.5281/zenodo.21419572.svg)](https://doi.org/10.5281/zenodo.21419572)

Interactive 3D globe viewer for the v4.0 pre-registered confirmatory phase of the
E8 lattice alignment investigation: does an optimally oriented projection of the
E8 root system's edge network align with a fixed catalog of 157 sites more
closely than search-optimised random controls?

Live viewer: https://salahealer9.github.io/e8-globe-viewer

## What it shows

- The supported E8 edge network (edges within 0.10° of ≥ 1 site) for each
  projection seed, rendered as great-circle arcs.
- The 157 catalog sites, colored by distance to the nearest E8 edge of the full
  6720-edge grid (**display bins only — not significance thresholds**).
- Per seed: the search-aware null distribution (1000 best-of-search trials) with
  the real RMS marked, plus p-value, z, Cohen's d, and BH-FDR status.
- Shared edges ("ley lines") passing near 2+ sites, with the site pairs named.
  Edges are colored by support tier: gold (1 site), platinum (2 sites), rose
  (3+ sites).
- A sortable, filterable distance table of all 157 sites, including each site's
  engine-computed count of supported edges within tolerance (hub sites at a
  glance; outliers at 0).

## Interactions

- **Search** any of the 157 sites (autocomplete) to fly there; click a site for
  its name label and distance readout; click a shared edge for the sites it
  connects.
- **Distance table**: sort by any column, filter by name, click a row to fly
  there; selections stay in sync between globe, search, and table.
- `←` / `→` cycle through seeds; the seed selector groups by BH status.
- **Compare seeds** splits the view into two camera-synchronized globes — e.g.
  an elite seed vs. a control — with per-side seed selectors and search.
  Selecting a site mirrors onto both globes with each seed's own distance. A
  bottom toolbar provides reset view, fly-to-anchors (each globe to its seed's
  lock point), basemap toggle, and exit (`Esc` also exits).
- The URL hash tracks the view — `#seed788` for a single seed,
  `#seed788-vs-797` for a comparison — so links open directly on that view.
- "Fly to anchor" centres the camera on the seed's locked orientation point;
  the basemap toggle switches dark (CARTO) ↔ light (OpenStreetMap) tiles. The
  camera can descend to ~2 km above the surface for close edge inspection.
- Each seed's panel shows the null histogram with a plain-language line —
  "k of 1000 search-optimised random rotations matched or beat the real RMS" —
  derived from the raw trial values (it reproduces the Monte-Carlo
  p = (k+1)/(n+1) exactly).

## The statistical claim, precisely

- The primary statistic is the **search-aware best-of-search RMS null**: each of
  1000 null trials gets the same orientation search the real catalog got.
- **BH-FDR at q = 0.05 was applied to the pre-registered 12-seed elite family**;
  10 of 12 survive. Seeds 1649 and 354 are not significant (uncorrected
  p = 0.054 and 0.059).
- **0 of 6 pre-registered control seeds are significant** (expected under null).
- No individual distance band (quantile threshold) is the claim; the signal is
  the family-level RMS result.
- **The signal is statistically robust; the mechanism is unknown. These are
  different claims.**

## Running

Any static server from this directory:

```
python -m http.server
# open http://localhost:8000
```

(Opening `index.html` directly via `file://` will not work — browsers block
`fetch()` of local data files.)

The dark basemap uses CARTO raster tiles with a public browser API key restricted
to the deployed website origin. The light basemap uses OpenStreetMap tiles.
No Cesium ion token is required.

Basemap imagery is streamed from CARTO
(dark, © OpenStreetMap contributors © CARTO) and OpenStreetMap (light).
An offline imagery fallback is not bundled, so a network connection is required
for the basemap. CesiumJS itself is also loaded from CDN.

## Data provenance & verification

All files in `data/` are generated by `export_viewer_bundle.py` in the private
`earthgrid-research` engine repository — nothing in this viewer is hand-edited.
`data/manifest.json` (schema 1.1) embeds the engine commit hash, catalog
SHA-256, generation timestamp, and export parameters. The per-seed statistics
are parsed directly from the engine's 1000-trial KS/best-of-search result
files; the viewer contains no hardcoded numbers.

`node verify_bundle.mjs` re-checks the entire bundle: strict-JSON parsing,
grid/manifest count consistency, shared-edge site-pair joins, agreement between
the exporter's per-site support counts and the KS full-grid distances at the
tolerance boundary, and exact reproduction of every reported Monte-Carlo
p-value from the raw null trials.
